# 基于轨迹自动识别场景类型工具 - 使用说明

## 功能简介

本工具通过分析车辆轨迹的几何特征与运动状态，自动识别测试场景类型，解决实车测试中事件标记信号缺失的问题。

### 支持的场景类型

| 场景类型 | 英文名称 | 识别依据 |
|---------|---------|---------|
| **变道** | `lane_change` | `lateral_error` 绝对值 ≥ 0.6m 且局部 `ref_kappa` < 0.003 1/m |
| **弯道** | `constant_curve` | `ref_kappa` 绝对值均值 ≥ 0.005，且持续占比 > 30% |
| **跟车起停** | `follow_stop_go` | 速度 < 0.5 m/s 停车，或频繁变速且最低速度 < 0.5 m/s |
| **直道** | `straight_hold` | 默认兜底（不满足以上任一条件） |

### 基本用法

```bash
cd C:\Users\huangjiangyu\Desktop\hirain\L4\train_file\tuneOnSite\roboVAN_tuneOnSite

python classify_scenario_from_trajectory.py --input your_log.csv --output output_dir
```

### 输入要求

**必需的 CSV 列**（内部标准名）：

| 内部名 | 说明 | 单位 |
|--------|------|------|
| `timestamp` | 时间戳 | 秒 |
| `x` | 自车 X 坐标 | 米 |
| `y` | 自车 Y 坐标 | 米 |

**可选的 CSV 列**（用于更精确的识别）：

| 内部名 | 说明 | 单位 |
|--------|------|------|
| `ego_v` | 自车速度 | m/s |
| `ref_v` | 参考速度 | m/s |
| `ref_kappa` | 参考曲率 | 1/m |
| `lateral_error` | 横向跟踪误差 | m |

**如果 CSV 列名与上述内部名不一致**（如真实数据使用 `position_enu.x` / `position_enu.y`），
请通过 `--signal-config` 参数指定列名映射文件。详见下方「列名映射」章节。

### 输出文件

执行完成后，输出目录将包含：

1. **`output_classified.csv`**：带场景标记的 CSV 文件
   - 添加了 6 个 event 标记列（`event_lane_change`, `event_curve_enter`, `event_curve_exit`, `event_follow_start`, `event_stop_start`, `event_stop_end`）
   - 可直接用于 `analyze_run.py` 分析

2. **`trajectory_with_scenario.png`**：轨迹可视化图（4 合 1）
   - 左上：轨迹俯视图（颜色区分场景）
   - 右上：曲率时序图
   - 左下：速度时序图（如果有速度数据）
   - 右下：场景时序图

3. **`scenario_report.txt`**：场景统计报告
   - 各场景的数据点数、时长、占比

## 命令行参数

### 必需参数

| 参数 | 说明 | 示例 |
|------|------|------|
| `--input` | 输入 CSV 文件路径 | `--input your_log.csv` |
| `--output` | 输出目录 | `--output classified_output` |

### 可选参数（信号映射）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--signal-config` | 无 | 信号配置 YAML 文件（内部名 → CSV 列名的映射）。当 CSV 列名与标准名不一致时必须指定 |

### 可选参数（阈值和窗口调整）

| 参数 | 默认值 | 说明 | 调整建议 |
|------|--------|------|---------|
| `--curve-kappa` | 0.003 | 弯道曲率阈值（1/m） | 调小使更多路段被识别为弯道 |
| `--lane-change-offset` | 0.6 | 变道横向偏移阈值（m），基于 `lateral_error` 判断 | 调小使更多路段被识别为变道 |
| `--window-size` | 100 | 滑动窗口大小（点数，用于特征提取） | 数据噪声大时增大 |
| `--step` | 50 | 滑动窗口步长（点数） | 通常保持默认 |

## 列名映射（重要）

### 适用场景

当输入 CSV 的列名与工具内部标准名不一致时（例如真实录制数据使用 `position_enu.x` 而非 `x`），
需要通过 `--signal-config` 参数指定列名映射文件。

### signal_config.yaml 格式

```yaml
# 格式：内部标准名: CSV 实际列名
timestamp: timestamp
x: position_enu.x           # 将 position_enu.x 映射到内部 x
y: position_enu.y           # 将 position_enu.y 映射到内部 y
ego_v: debug.simple_lon_debug.current_speed
lateral_error: debug.simple_lat_debug.lateral_error
ref_kappa: ref_kappa
# ... 其他字段
```

### 项目已含的配置文件

| 配置文件 | 适用数据源 |
|----------|-----------|
| `config/signal_config.yaml` | 真实录制数据（interpolated CSV，如 `*_interpolated.csv`） |
| `config/signal_config_accelerate.yaml` | 加速场景数据（accelerate 目录） |

> **提示**：对于 sample 数据（`sample_data/sample_run.csv`），列名已匹配标准名，无需指定 `--signal-config`。

## 阈值调整指南

### 问题 1：弯道识别太少

**症状**：实际是弯道，但识别为直道

**解决方案**：调小 `--curve-kappa`

```bash
python classify_scenario_from_trajectory.py \
  --input your_log.csv \
  --output output_dir \
  --curve-kappa 0.002  # 默认 0.003 → 调小为 0.002
```

### 问题 2：弯道识别太多

**症状**：直道被识别为弯道

**解决方案**：调大 `--curve-kappa`

```bash
python classify_scenario_from_trajectory.py \
  --input your_log.csv \
  --output output_dir \
  --curve-kappa 0.004  # 默认 0.003 → 调大为 0.004
```

### 问题 3：变道识别太少

**症状**：实际是变道，但识别为直道

**解决方案**：调小 `--lane-change-offset`

```bash
python classify_scenario_from_trajectory.py \
  --input your_log.csv \
  --output output_dir \
  --lane-change-offset 0.4  # 默认 0.6 → 调小为 0.4
```

### 问题 4：变道识别太多

**症状**：直道上的小横向偏移被误识别为变道

**解决方案**：调大 `--lane-change-offset`

```bash
python classify_scenario_from_trajectory.py \
  --input your_log.csv \
  --output output_dir \
  --lane-change-offset 0.8  # 默认 0.6 → 调大为 0.8
```

### 问题 5：场景频繁切换

**症状**：场景标签频繁抖变（如直道 - 弯道 - 直道 - 弯道连续交替）

**解决方案**：平滑窗口大小已在代码中固定。独立 CLI 模式下平滑窗口为 10 个点；通过 `data_process` 管线调用时，可通过 `--smooth-window` 参数调整（默认 5）。

## 常见问题

### Q1: 报错 "No module named 'scipy'"

**解决方案**：
```bash
pip install scipy matplotlib pyyaml
```

### Q2: 报错 "缺少必需列：['x', 'y']"

**原因**：CSV 中的列名不是 `x`、`y`（如真实数据使用 `position_enu.x`、`position_enu.y`）。

**解决方案**：添加 `--signal-config` 参数：
```bash
python classify_scenario_from_trajectory.py \
  --input your_log.csv \
  --output output_dir \
  --signal-config config/signal_config.yaml
```

### Q3: 识别结果与实际情况不符

**可能原因**：
1. 阈值不合适 → 根据「阈值调整指南」调整 `--curve-kappa` 或 `--lane-change-offset`
2. `lateral_error` 列缺失或值异常 → 变道检测依赖 `lateral_error`，确认列名映射正确且数值合理
3. 列名映射错误 → 检查 `signal_config.yaml` 中的映射是否正确

**调试步骤**：
1. 查看可视化图，确定哪种场景识别错误
2. 根据「阈值调整指南」调整对应参数
3. 重新运行，对比效果

### Q4: 输出 CSV 中的 event_* 列全为 0

**可能原因**：
1. 所有数据都被识别为 `straight_hold`（直道）——场景边界无变化，event 标记自然不会触发
2. 数据中确实没有场景切换

**解决方案**：
1. 查看 `scenario_report.txt`，确认场景分布
2. 如果确实都是直道，说明测试路线单一或阈值过严
3. 调整阈值使识别更敏感

### Q5: 如何处理长数据（>1 小时）？

**建议**：
1. 逐点分类模式下性能与数据量成正比，约万行/秒
2. 对于超长数据（>10 万行），建议先降采样或分段处理

## 技术细节

### 分类流程（三步管线）

本工具的主入口函数为 `classify_trajectory_pipeline()`，采用三步管线处理：

**Step 1 — 逐点分类（`classify_scenario_direct`）**

对每一帧数据独立判定场景类型，按优先级依次检查：

1. **弯道**：局部窗口内 `ref_kappa` 绝对值均值 ≥ 0.005，且持续超出占比 ≥ 30%
2. **跟车起停**：`ego_v` < 0.5 m/s（停车），或局部窗口内频繁变速且最低速度 < 0.5 m/s
3. **变道**：`lateral_error` 绝对值 ≥ 0.6m 且局部 `ref_kappa` < 0.003 1/m
4. **直道**：以上均不满足时兜底

**Step 2 — 段级修正**

对连续轨迹分段（`window_size=100, step=50`），按优先级覆盖：

| 优先级 | 场景 | 修正条件 |
|--------|------|---------|
| 1（最高） | `lane_change` | 段内横向偏移峰值 ≥ 0.6m，曲率低 |
| 2 | `constant_curve` | 段内 `ref_kappa` 均值 ≥ 0.003 或持续占比 ≥ 30% |
| 3 | `follow_stop_go` | 低速占比高且有停车/频繁变速 |
| 4 | 保留 | 兜底保留 Step 1 的逐点分类结果 |

**Step 3 — 标签平滑**

使用多数投票（majority voting）对场景标签进行平滑：
- 独立 CLI 模式：窗口大小固定为 10 个点
- `data_process` 管线模式：默认窗口 5 个点，可通过 `--smooth-window` 调整

### 场景识别优先级

1. **弯道**（`ref_kappa` 曲率特征最明显）
2. **跟车起停**（速度特征）
3. **变道**（`lateral_error` 横向偏移）
4. **直道**（默认兜底）

### 事件标记生成

根据场景标签的变化生成 6 类事件标记：

| 事件列 | 触发条件 |
|--------|---------|
| `event_lane_change` | 处于变道场景段内 |
| `event_curve_enter` | 处于弯道场景段内 |
| `event_curve_exit` | 从弯道切换到非弯道场景的边界点 |
| `event_follow_start` | 处于跟车起停场景段内 |
| `event_stop_start` | 跟车场景中速度降至 < 0.3 m/s |
| `event_stop_end` | 跟车场景中速度升至 ≥ 0.3 m/s |
